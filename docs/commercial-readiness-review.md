# TIU Worldgame Commercial Readiness Review

작성일: 2026-05-18

## 1. 현재 제품 요약

TIU Worldgame은 텍스트 기반 AI 세계관 탐험 게임이다. 현재 버전은 비공개 테스트용 구조에 가깝고, 플레이어는 시작 루트나 캐릭터 컨셉을 선택한 뒤 AI-GM이 장면, 선택지, 브리핑, 기억, 이미지 매칭을 생성한다.

현재 강점은 세계관의 밀도, 어두운 조사물 톤, 이미지 에셋, 선택지 중심 플레이, 저장/요약/피드백/진단 기능이 이미 한 앱 안에 연결되어 있다는 점이다. 반대로 상업용으로 가려면 "AI 채팅 도구"가 아니라 "증거를 따라가는 게임 시스템"으로 더 선명하게 고정해야 한다.

## 2. 현재 구현 체크

### 구현 완료 또는 동작 확인

- Next.js 기반 웹 앱, 로컬 개발 서버 `http://localhost:3001`.
- OpenAI API 호출 경로 및 모델 프로필 기본 구조.
- Claude/Anthropic 모델 선택 준비 구조. 현재 진단 기준 Anthropic API는 미설정.
- 선택지 중심 AI-GM 응답, 직접 입력 최소화 방향.
- 시작 루트 3종: 한국 방벽 내부, KR-INIT-001, 남극 거대공동 현장 파견.
- 자유 캐릭터 시작, 스트리머/유튜버 계열 시작 처리.
- 세계관 민감 정보는 증거 기반으로만 공개하도록 프롬프트/규칙 구성.
- canon 인물 직접 플레이 차단: 이중철, 베버, 서하은 등과 직접 관계 사칭 시작 차단.
- 요약 메모리, 플레이어 메모, 자동 메모리, 사건 로그, 현재 세션 저장.
- 세이브/로드, 세션 라이브러리, 내보내기/가져오기, 비공개/검토 대기 아카이브 흐름.
- 관리자 진단 API, 테스트 피드백 API.
- 월드 인덱스 생성: 로컬 Obsidian/세계관 폴더에서 `world/index/world-index.local.json` 생성됨.
- 이미지 매칭: `public/assets/user-scenes` 기준 77개 이미지와 manifest 확인됨.
- QA 스크립트: `npm run qa:local`, `qa:smoke`, `qa:regression`.

### 최근 개선 완료

- 시작 루트 카드 문구를 업무 설명형에서 "이상한 단서와 첫 의문" 중심으로 변경.
- 고정 시작 장면 3종을 더 짧고 대화 중심으로 재작성.
- AI-GM 프롬프트에 `Curiosity Loop Rule` 추가.
- 기본 응답 형식에서 `[Action Read]`, `[World Response]`를 routine 구조가 아닌 필요 시에만 쓰도록 완화.
- `npm run qa:local` 통과.

### 즉시 점검 필요

- 관리자 진단 기준 `privateGateConfigured: false`로 확인됨. 비공개 테스트를 유지하려면 배포 환경과 로컬 `.env.local` 모두에서 `TIU_ACCESS_PASSWORD` 계열 설정을 확인해야 한다.
- 저장소가 현재 로컬 JSON 파일 기반이다. Vercel 배포 환경에서는 영구 저장소가 아니므로 상업 운영에는 DB/Blob 스토리지가 필요하다.
- `world-index.local.json`은 로컬 전용 파일이다. 배포판에서 세계관 검색을 쓰려면 공개 가능한 정제 인덱스 `world/index/world-index.json` 또는 서버 저장소 기반 검색 인덱스가 필요하다.

## 3. 게임성 평가

### 차별점

- AI Dungeon식 자유 즉흥 모험보다, "증거 기반 공개", "숨겨진 세계관", "문서/제보/기록/현장" 중심이라는 방향이 있다.
- 일반 판타지/생존물이 아니라 신화, 음모론, 국가, 기관, 설명되지 않는 존재가 겹치는 조사물이다.
- 이미지를 상황에 맞게 붙일 수 있어 텍스트만 있는 AI 채팅보다 장면성이 강하다.
- 선택지 중심 구조로 플레이어가 매번 문장을 직접 쓰지 않아도 진행 가능하다.

### 현재 약점

- 아직 핵심 게임 루프가 "AI가 다음 장면을 잘 써주기"에 많이 기대고 있다.
- 단서, 인물, 위험, 신뢰, 의심, 공개 등급이 UI에는 보이지만, 별도 게임 규칙 엔진처럼 강하게 잠겨 있지는 않다.
- 장면이 조금만 길어지면 다시 보고서/업무 지시 느낌으로 돌아갈 위험이 있다.
- 실패, 부분 성공, 우회 성공, 관계 변화 같은 플레이 결과가 아직 수치/상태로 충분히 누적되지 않는다.
- 선택지의 질을 자동 검증하는 테스트가 부족하다. 현재 회귀 테스트는 포함/제외 단어와 기본 구조 중심이다.

## 4. 상업용 핵심 개선 우선순위

### P0: 비공개/소수 테스트 안정화

1. 생산용 저장소 분리
   - 세션, 메모리, 피드백, API 사용량, 사용자 계정을 DB에 저장.
   - 이미지와 세션 export 파일은 Blob/S3 계열에 저장.
   - 현재 `world/session/*.json`은 로컬 개발 및 백업용으로만 유지.

2. 접근/계정 보안
   - 비밀번호 게이트 설정 확인.
   - admin 기본 계정 `admin / 0000`은 테스트 후 반드시 변경.
   - 계정별 세션 분리, 역할 분리, 로그아웃/세션 만료, 계정 삭제 흐름 필요.

3. 비용/속도 제어
   - 사용자별 일일 호출/토큰 제한.
   - 모델별 비용 추적.
   - 스트리밍 응답 또는 단계별 응답 표시.
   - world index 검색 결과 캐싱.
   - 실패 시 짧은 재시도, 모델 fallback, 응답 비어 있음 감지.

4. 게임 루프 엔진화
   - `CaseState`: 현재 사건, 증거, 공개 등급, 위험도, 목표.
   - `ClueRegistry`: 발견 전/발견 후/검증 완료 단서.
   - `NpcState`: 신뢰, 감정, 알고 있는 정보, 숨기는 정보.
   - `DisclosureGate`: 민감 정보별 공개 조건.
   - `ChoiceGenerator`: 선택지가 단서/인물/위험 상태를 반영하도록 규칙화.

5. 직접 입력 게이트
   - 기본은 선택지 플레이.
   - 특정 장면에서만 "질문 입력" 또는 "짧은 답변 입력" 열기.
   - 직접 입력 결과는 다음 선택지 품질에 영향을 주는 구조로 제한.

### P1: 폐쇄 베타 완성도

1. 첫 10분 온보딩
   - 플레이어가 세계관을 공부하지 않아도 바로 궁금해지는 첫 사건 3개.
   - 각 루트는 15~20분 안에 작은 결론을 볼 수 있게 설계.

2. 장면 품질 평가
   - "최근 선택 반응", "새 단서 1개", "인간 접점", "다음 선택 압박"이 있는지 자동 검사.
   - 너무 긴 세계관 설명, 반복 단어, unrelated route drift 감지.

3. 모바일 UI
   - 브리핑은 기본 접힘.
   - 선택지는 손가락으로 누르기 편한 높이 유지.
   - 저장/메뉴/메모/AI 추천은 한 메뉴 안에서 정리.

4. 이미지 파이프라인
   - 파일명 키워드 의존을 줄이고 manifest에 태그, 공개 등급, route, scene type 저장.
   - 상업 배포 가능한 권리 상태를 에셋마다 기록.

5. 한영 품질 동등화
   - UI i18n뿐 아니라 시작 장면, 고정 루트, 에러, 안전문구, 공개 등급 명칭도 KO/EN 동등화.
   - 영어 플레이 시 고정 opening을 영어로 반환하는 경로 추가.

### P2: 출시 준비

1. 결제/크레딧/쿼터
   - 무료 체험, 유료 토큰, 월 구독 중 하나를 먼저 고정.
   - 응답 길이 배수는 내부 비용 단위로만 표시하고, 실제 토큰/원가 노출은 관리 화면으로 분리.

2. 스토어/웹 정책 문서
   - 개인정보처리방침.
   - 이용약관.
   - AI 생성 콘텐츠 고지.
   - 사용자 생성 세션 공유 정책.
   - 환불/문의/삭제 요청 절차.

3. 콘텐츠 안전 및 등급
   - 청소년 이용 가능 범위를 목표로 할지, 성인 조사물로 갈지 결정.
   - 폭력, 공포, 자해, 미성년자, 성적 콘텐츠, 실제 범죄 방법론 필터링.
   - 신고/차단/관리자 검토 큐.

4. 운영 도구
   - 관리자 대시보드: 사용자, 세션, 비용, 피드백, 신고, 모델 장애.
   - 프롬프트/세계관 인덱스 버전 관리.
   - 핫픽스 가능한 route playbook.

## 5. 있으면 좋은 게임 기능

| 기능 | 장점 | 단점/주의 |
| --- | --- | --- |
| 사건 보드 | 플레이어가 단서를 모으는 게임 감각이 생김 | UI가 커지면 몰입 방해, 기본 접힘 필요 |
| 추론/가설 슬롯 | 플레이어가 직접 "믿는 것"을 정하게 됨 | AI가 정답을 너무 빨리 인정하면 재미 감소 |
| NPC 신뢰/감정 변화 | 인간적인 대화와 관계가 살아남 | 수치가 노출되면 게임적이지만 인공적으로 보일 수 있음 |
| 공개 등급 게이트 | 민감 정보가 천천히 열려 세계관 가치 보호 | 조건이 불투명하면 답답함, 힌트 필요 |
| 장면 이미지 로그 | 플레이 장면이 기억에 남고 공유성 증가 | 에셋 권리/태그 관리가 필요 |
| 세션 요약 카드 | 다음날 이어하기 쉬움 | 너무 긴 자동 요약은 다시 피로해짐 |
| 스트리머 모드 | 방송 친화적, 스포일러/민감 정보 가림 | 채팅 연동은 악용/개인정보 리스크가 있음 |
| 짧은 에피소드 모드 | 상업 베타에서 완성감이 잘 보임 | 무한 자유도 기대와 충돌 가능 |
| 플레이 후 보고서 | 플레이어 선택 결과가 남음 | 보고서가 길면 다시 업무문 느낌 |
| 테스트 피드백 버튼 | 폐쇄 테스트에서 개선점 수집 쉬움 | 스팸/중복 정리 도구 필요 |

## 6. 법무/정책/플랫폼 체크

상업용 체크는 법률 자문이 아니며, 출시 전 별도 검토가 필요하다.

- Steam 배포를 고려한다면 AI 생성 콘텐츠 사용 방식을 스토어 등록 과정에서 설명해야 한다. Valve는 사전 생성 AI와 실시간 생성 AI를 구분하고, 실시간 생성 콘텐츠에는 불법 콘텐츠 생성을 막는 가드레일 설명을 요구하는 방향으로 정책을 운영한다고 공지했다.
- 모바일 앱으로 확장할 경우 Apple App Store 가이드라인의 사용자 생성 콘텐츠, 신고/차단, 모더레이션 요구를 고려해야 한다.
- OpenAI API는 기본적으로 API 입력/출력을 모델 학습에 사용하지 않는 정책을 안내하지만, 서비스 운영자는 자체 개인정보 처리방침과 사용자 고지를 별도로 제공해야 한다.
- Anthropic API도 일반적으로 고객 입력/출력을 모델 훈련에 사용하지 않는다고 안내하지만, 제공자별 데이터 보존/옵트인 조건은 배포 전에 최신 문서로 다시 확인해야 한다.
- 등급 심사는 IARC/ESRB 계열 설문에서 폭력, 공포, 사용자 상호작용, 온라인 콘텐츠, AI/UGC 요소를 고려해야 한다.
- 현재 이미지 에셋은 상업 사용 가능 여부, 생성/구매/직접 제작 여부, 원본 파일, 라이선스를 manifest에 기록해야 한다.

## 7. 추천 개발 순서

1. 현재 비공개 테스트 유지: 비밀번호 게이트, admin 비밀번호, Vercel env 점검.
2. 로컬 JSON 저장소를 DB/Blob 추상화로 교체할 설계 작성.
3. `CaseState`, `ClueRegistry`, `NpcState`, `DisclosureGate` 타입부터 추가.
4. 시작 루트 3개를 각각 15분짜리 "짧은 완결 사건"으로 설계.
5. 선택지 품질 테스트 추가: 대화형 선택지, 장면 길이, unrelated drift, 직접 입력 차단.
6. 이미지 manifest에 route/tag/license 필드 추가.
7. 폐쇄 테스터용 피드백/진단 화면을 관리자 메뉴에서 보기 좋게 정리.
8. 개인정보처리방침/AI 고지/테스터 약관 초안 작성.
9. 비용 정책: 무료 테스트 한도, 유료화 단위, 모델 fallback 결정.
10. 폐쇄 베타 후 10~20개 플레이 로그를 분석해 루프를 다시 조정.

## 8. 결론

상업성이 없는 상태는 아니다. 오히려 세계관과 톤은 강하다. 다만 지금의 위험은 "AI가 이야기를 써주는 앱"으로 보이는 것이다.

상업용 제품으로 선명해지려면 핵심 포지션을 이렇게 잡는 것이 좋다.

> "자유 채팅형 AI 던전"이 아니라, 증거와 기록을 따라 숨겨진 세계관을 여는 AI 조사 어드벤처.

이 방향이면 AI Dungeon과 직접 비교되는 약점을 줄이고, TIU만의 강점인 문서, 기록, 은폐, 공개 등급, 이미지 에셋, 세계관 탐색을 게임성으로 만들 수 있다.
## 9. 2026-05-18 Rules Engine Phase 1

이번 단계에서 상업용 포지션을 "AI Dungeon류 자유 채팅"이 아니라 "증거와 기록을 따라 숨겨진 세계관을 여는 AI 조사 어드벤처"로 고정하기 위한 1차 규칙 엔진을 붙였다.

구현된 상태:
- `CaseState`: 현재 사건, 루트, 진행 단계, 공개 등급, 위험도, 현재 질문, 장면 압박을 서버 응답에 포함한다.
- `ClueRegistry`: 루트별 기본 단서와 브리핑에서 추출된 단서를 병합하고 `noticed`, `collected`, `verified`, `contradicted` 상태로 관리한다.
- `NpcState`: 루트별 반복 NPC와 브리핑 인물을 병합해 감정, 관계, 신뢰도, 마지막 접점을 관리한다.
- `DisclosureGate`: 민감 정보나 숨겨진 세계관을 바로 설명하지 않고, 필요한 단서가 모였을 때 `locked`, `hypothesis`, `unlocked` 단계로 열리도록 상태를 만든다.
- `/api/chat` 프롬프트에 현재 게임 엔진 상태를 주입해, AI-GM이 선택지를 단서 수집, 단서 검증, NPC 질문, 기록 대조, 공개 게이트 테스트 중심으로 만들도록 했다.
- 세션 저장/복원 정규화에서 `engine` 필드를 보존한다.
- 회귀 QA가 `CaseState`, `ClueRegistry`, `NpcState`, `DisclosureGate` 누락을 감지하도록 확장됐다.

다음 단계:
1. 브리핑 UI에 엔진 상태를 노출하되, 몰입을 해치지 않도록 "사건 단계 / 단서 수 / 잠긴 기록" 정도의 작은 HUD로 정리한다.
2. 플레이어 선택지가 어떤 단서/NPC/게이트를 겨냥했는지 명시적으로 기록하는 `ActionIntent`를 추가한다.
3. 단서가 실제로 검증됐는지 판정하는 서버 측 전이 규칙을 더 촘촘히 만든다.
4. 루트별 사건 보드를 만들어 플레이어가 지금까지 모은 증거와 아직 잠긴 기록을 한눈에 볼 수 있게 한다.
